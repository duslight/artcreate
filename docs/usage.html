一、升级报告：从「美术生图管线」到 artcreate

最初版本（art_pipeline，809 行 Python + 341 行单页）解决的是「把表单变成英文 prompt 并出图」这一件事。 当前版本（artcreate，3994 行 Python + 2300 行工作台 + 580 行结构化字典）是一条带质量门禁、带资产库、带经验回写的完整生产线。下表是全貌对比：

维度旧art_pipeline新artcreate v1.0
定位表单 → prompt → 出图的演示工具三产线（场景/角色/怪物）标准化美术资产生产线
架构6 个平铺 .py，单进程内存队列（重启即清）分层包（tools / gates / web）+ SQLite 资产库 + 后台 worker 队列（重启可续查）
字典硬编码 config.py（改一次重启一次）三层配置链 base.yaml → project.yaml → derived/*.yaml 深合并，选项级人话 desc / 溯源徽标
资产类型5 种（全场景向）8 种：场景 5 + 角色立绘/前后视图 + 怪物立绘（applies_to 按页过滤）
约束轴4 条（人工痕迹/水体/空间/植被，全场景）14 条分线轴：场景 4 + 角色 5（取景/背景/朝向/姿势）+ 怪物 7（背景/体型结构/尺度/威胁定位/标志特征/皮肤材质/威胁基调），每档带注入词中英对照与验图问句

编译器v2：LLM 全字段编译，扩展词易与用户约束打架（如「纯色背景」轴被环境扩展顶掉）v3：约束前置（轴正向+自由约束先于 LLM 扩展注入，且作为必守上下文）；审核直通（所见即所执行）；模式级强制负向配置化（forced_negative：场景/怪物默认排除 people，角色页不排）
质量门禁无四层：L1 lint（负向注入/画风冲突/token 超限/枚举合法性）+ L2 编译自检（LLM 反向核对忠实度）+ L3 意图回查（VLM 按验图问句验成图）+ L4 跨批统计；另加机械门禁四项（调色板/网格规则度/alpha 边缘/尺寸精确）

角色一致性无锚点管线：首张立绘「设为锚点」→ 后续生成自动挂参考图 + dHash 一致性检查；三槽参考图（人物/画风/姿势各 1 张，分工说明句直送模型）
怪物设计无独立怪物页：剪影优先方法论落成 7 条轴，独立三槽参考图库（与角色库隔离）
经验沉淀无distill 蒸馏拍板理由 → LLM 判定 → 晋升为字典选项（derived/*.yaml 自动 git 留痕，可 promote/demote）

1.1 编译器进化细节（v2 → v3）

prompt 结构：资产前缀 → 场景翻译 → 轴正向 + 正向自由约束（前置！） → LLM 扩展词 → 氛围注入 → 氛围注记 → 画风尾块 → Strictly avoid: 排除块（轴负向+模式强制负向+自由负向，全局去重） → 参考图分工说明句
  • 为什么约束要前置：旧版扩展词夹在场景与约束之间，LLM 拿到的扩展指令还写死「家具/物件/建筑/绝不出人」——对要画人的角色页是矛盾指令，也会把「纯色简洁背景」轴顶掉。新版轴正向同时进 META_PROMPT 的必守上下文（REQUIRED positive constraints），纯色背景时明令禁止扩展环境细节。
  • 追加描述通道已删：旧版 extra_prompt 前端早已无输入入口，v3 彻底删除该通道（pose/三视图等管线内部语料改走自由约束，编译路径统一）。
  • 审核直通：你在审核卡确认过的编译词原样执行（compiled_prompt），杜绝「审核的和执行的不一致」——LLM 重编译有随机性。
  • 强制负向配置化：旧版无脑追加 people 排除（角色页也排，自相矛盾）；新版 base.yaml 配置 forced_negative: {scene: [people], character: [], monster: [people]}，改配置即可调整。

1.2 质量门禁四层（旧版完全没有）

层名字做什么拦什么
L1编译前 lint纯规则静态扫描，零成本「不要X」式否定注入（生成模型反向激活）、画风冲突词、token 超限截断、枚举值写错静默失效
L2编译自检第二个 LLM 反向核对编译产物翻译丢意、越权加戏（prompt 里出现表单没要求的东西）
L3意图回查VLM 拿用户原始约束直接验成图图不对题（每条轴选项带 verify_question，如「画面是否完全没有人工建筑？」）
L4跨批统计统计历史通过率某类约束长期不生效 → 暴露字典或编译问题
机械机械门禁像素级程序检查调色板超色、网格不规则、边缘半透明、尺寸不符（按画风可放宽，如暗黑地牢手绘风 4096 色）

二、使用说明

2.1 快速开始

cd artcreate
python -m venv .venv
.venv\Scripts\activate            # Windows；Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # 填 ARK_API_KEY（生图）与 ZHIPU_API_KEY（编译/验图）
python -m artcreate serve         # 启动工作台
# 浏览器打开 http://127.0.0.1:8870/workbench.html

服务器部署（公网访问）须配置环境变量 WORKBENCH_TOKEN（访问令牌），详见 deploy/README.md。手机端可用 http://<IP>:8870/workbench.html?token=<令牌> 直连。

2.2 三条产线怎么选

页面产什么核心机制
场景 / 静物场景全景、背景底图、单体物件、卡面、纹理4 条场景轴（人工痕迹/水体/空间/植被）+ 9 种氛围光影 + 迭代载入（parent_run 溯源）
角色生成角色立绘（形象基准）→ 前后视图 → 动作变体首张拍板后「设为锚点」；三槽参考图（人物管长相/画风管笔触/姿势管构图）；5 条角色轴
怪物生成非人形生物设定图剪影优先方法论：7 条怪物轴（背景/体型结构/尺度/威胁定位/标志特征/皮肤材质/威胁基调）；独立三槽参考图库

三条线共用同一编译/门禁/入库链路，差异全部在字典层（applies_to 过滤），不写死代码。

2.3 单次生成完整流程

填表（描述/类型/画风/尺寸/数量/约束轴/自由约束） → 提交 → 编译审核卡（中英对照+lint） →［可选 精修］→ 确认生成（扣费出图） → 后处理（像素化/量化） → 门禁 → 候选拍板（接受/拒绝/再生成） →［角色/怪物：设为锚点］→ 命名发布 exports/final/
  1. 填表：中文一句话描述即可，翻译交给编译器。约束轴点选后下方即时显示注入/排除词的中英对照。负向自由约束栏：场景/怪物页默认已排除人类，只写额外要排除的东西（例：蜘蛛、翅膀）。
  2. 编译审核（提交后弹出）：上半部是完整英文 prompt 与其中文翻译，下半部分段解释每段从哪来（字典注入/LLM 扩展/你的输入）。有 ⚠️ lint 警告可回去改；「Strictly avoid:」句是排除块，独立于正文。
  3. 精修模式（可选）：整段直改（默认）——直接改中文全文，LLM 逐句对齐只重译改动部分；分段模式——改某段中文，对应英文段同步重译，其余原样保留。
  4. 确认生成：每张成本约 0.2 元（方舟 Seedream 4.5）。数量默认 1，先看效果再加量。
  5. 候选拍板：出图区逐张检查（L3 验图结果标注在旁）。接受 → 入库；拒绝 → 可「拒绝并再生」（自动带 parent_run 与修正语料）。全部处置完出图区自动收起。
  6. 设为锚点（角色/怪物页）：把当前候选立为形象基准，之后该角色的所有生成都自动挂此参考图并跑一致性检查。
  7. 命名发布：资产名（如 alice）+ 后缀（_v2/_alt/_icon…）→ 发布到 exports/final/ 交付库。

2.4 动作批量（动画帧）

「动作 / 特效」页选角色（须已有锚点）+ 勾选动作（待机/行走/攻击/受击/技能/倒地/起手/跳跃/冲刺）→ 每动作一个 run，自动挂锚点参考图 + dHash 一致性检查，批量产出动画帧序列。

2.5 历史与迭代

  • 从历史载入：场景页可点选最近 30 条 run 载入表单，作为新迭代的起点（自动记 parent_run）。
  • 沿用历史编译词：载入后审核卡提供「沿用上次编译」——底稿直接进精修模式改，不必从零重译。
  • 评审视图：工作台内嵌评审 tab，看全部候选/门禁详情/操作时间线。

2.6 CLI 速查（自动化/脚本化用）

python -m artcreate run specs/xxx.yaml      # 跑一批（编译→生成→后处理→门禁→入库）
python -m artcreate compile specs/xxx.yaml  # 只编译看 prompt（不花钱）
python -m artcreate lint specs/xxx.yaml     # 只跑 L1 静态检查
python -m artcreate list [--status gated]   # 列候选
python -m artcreate select <subject>        # 拍板选定稿
python -m artcreate reject <run> <index>    # 拒绝某候选
python -m artcreate regenerate <run_id>     # 从历史 run 再生
python -m artcreate stats                   # L4 跨批统计
python -m artcreate anchor set <char> <img> # 手动设锚点
python -m artcreate poses <char> idle,walk  # 动作批量
python -m artcreate distill / proposals / promote / demote   # 经验蒸馏与晋升

2.7 配置体系（改行为不改代码）

层文件谁写典型用途
出厂artcreate/base.yaml随代码发布全部字典与默认值（约束轴/画风/氛围/动作/后缀/强制负向）
项目project.yaml你手写本游戏定制：默认画风/尺寸/数量、provider 密钥环境、门禁阈值
晋升derived/*.yamldistill 自动写拍板经验晋升成的字典选项（带置信度，git 留痕）

三层深合并：dict 按键覆盖、列表按 id 合并（同 id 递归、新 id 追加）。想在项目里加一条「教堂」人工痕迹选项？在 project.yaml 写同 id 轴追加 option 即可，base 不动。

2.8 密钥与安全

  • 密钥一律走 .env 环境变量（ARK_API_KEY / ZHIPU_API_KEY / WORKBENCH_TOKEN），仓库不接收任何真实密钥。
  • 生图走火山方舟 Seedream 4.5；编译/验图走智谱 glm-4-flash / glm-4v-flash（成本低）。provider 可在 project.yaml 热插拔，也支持「自定义 API」（方舟兼容端点）。
